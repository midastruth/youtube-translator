# 主 Agent + 子 Agent 翻译（默认 document 引擎）

## 工作方式

```text
获取字幕 → 清洗、断句，固定 cue_id / 时间轴
                ↓
主 Agent 快速阅读代表性上下文，评估风格、受众、语气与术语
                ↓
dispatch_subagents：共享规范，分派开头专用 Agent + 最多 9 个后续 Agent
                ↓
各 Agent 独立连续推进，每完成一回合就保存，不逐轮互等
                ├─ 开头 Agent（约视频前 1/6）优先完成；每个子 Agent 自查、校验并提交后立即推送该片段预览
                ↓
全部片段完成，宿主自动生成 review_checklist（启发式问题清单 + 片段交界对照）
                ↓
主 Agent 先处理清单，再用 read_bilingual 双语对照审阅，修正术语、语义与片段衔接
                ↓
同一回合：accept_translation → close_subagents → validate_translation → finish_translation
                ↓
宿主复核、原子发布
```

主 Agent 根据内容与任务大小决定开头范围和其余子 Agent 数量，不是每次固定启动满额。新任务额外配置 1 个开头专用 Agent，加上最多 9 个后续 Agent（合计最多 10 个）；极短任务可以只有开头 Agent。主、子 Agent 使用同一模型和 token 配置，但可分别设置推理强度，并有独立工具会话和工作区。子 Agent 是独立模型会话，不是宿主机子进程；宿主并发执行模型调用，不授予 shell 或任意外网权限。

入口不变：扩展选择 `document`，通过 `POST /api/subtitle/stream` 或 WebSocket 提交。`legacy` 快速模式保持原样。仅支持 `document` 与 `legacy`，旧 `agent` 枚举已移除。

## 扩展播放附近的 legacy 临时译文

扩展在 document 原文到达后，通过 `POST /api/subtitle/translate-window` 为当前播放位置前 10 秒、后 45 秒内尚无译文的字幕请求 legacy 上下文翻译。一次最多 12 条、合计 12000 字符，单窗口串行；优先当前和后续字幕，不翻译整部视频。请求包含 `playback_ms`、`source_language`、`translate_to` 及带原始 `index` 的 `source_cues`（毫秒）；服务端验证窗口和上限，直接翻译，不获取字幕或重新断句。模型、端点和密钥沿用 document 配置。

显示优先级：document 正式译文 > document 已提交片段预览 > legacy 临时译文 > 原文。临时译文仅留在浏览器当前字幕会话中，不写入 document 检查点，不参与团队审校或发布。原文重放不会清空临时译文，迟到的 legacy 响应不能覆盖 document。成功结果就地复用；失败的字幕至少等待 30 秒再随播放事件重试，不阻塞 document。

拖动播放进度后，只翻译新窗口；不再相关或已被 document 完全覆盖的在途请求会取消。document 失败后附近兜底仍可继续；关闭翻译、导航、设置重载或 document 全文成功时取消。此机制由浏览器扩展驱动，单独调用 document SSE/WebSocket API 不会自动启动 legacy。额外 legacy 请求不计入 Agent 请求/Token 预算，会增加 API 费用；关闭翻译可停止附近兜底请求。

## 主 Agent：规划、分派、验收

主 Agent 先快速阅读开头和代表性的后文定义，形成共享规范，包括翻译风格、领域、语气、术语的源语言到目标语言映射；提示词要求避免在派发前逐页穷尽全文。宿主提供 `source_bounds`（首尾编号、总条数）和 `dispatch_suggestion`（开头及剩余连续分段），候选已经完整覆盖原文，模型只需按需检查和调整边界，不必读完全篇才知道如何覆盖。候选按条数及附近句末/停顿生成，**不是语义章节识别结果**。

每解读一页后，提示词要求先用 `save_plan({summary})` 保存累计理解、风格、术语决定与未解决问题，再继续读取。宿主另行记录实际返回的原文读取范围。摘要与范围在每回合检查点中持久化，在 `workspace_status.main_progress` 中恢复；读取范围不代表模型已经理解内容。随后调用 `dispatch_subagents`，提供：

- `brief`：所有子 Agent 共享的不可变翻译规范与术语表。
- `opening`：`{end_id,instructions}`，从第一条原文开始的开头专用片段。长度与视频时长成正比：约为视频前 1/6（例如 1 小时视频约前 10 分钟）。宿主按时间轴计算 `opening_target`（建议 `end_id` 与允许范围，约目标时长的 0.75～1.5 倍；短视频建议并允许至少前 30 条）告知主 Agent，主 Agent 在范围内选择附近的句子/话题边界；超出范围的派发会被拒绝并提示重选。
- `assignments`：0～9 个按原文顺序排列的 `{start_id,end_id,instructions}`，覆盖开头之后的剩余原文。只有开头已覆盖全文时才允许为空。

程序检查片段必须完整覆盖全部字幕，不能重叠、遗漏、乱序或引用未知编号。派发只允许一次；主 Agent 在子任务完成后直接编辑合并译文来修正问题。

子任务执行期间主 Agent 等待，不额外调用模型。完成后主 Agent 回到原会话，读取实际译文，对照原文检查语义、术语和片段边界，必要时精确修改。

### 验收提速

- **双语对照读取 `read_bilingual({offset,count})`**：一页返回 `[cue_id, 原文, 译文或 null]` 行，不含时间轴、不缩进；`count` 必须显式选择（1～400，无默认值），页面受输入预算 25% 约束自动缩小，按 `next_offset` 续读。一次调用代替原文、译文各读一次，同等上下文可审阅约 2～3 倍字幕，减少回合数和上下文压缩。
- **自动检查清单 `review_checklist`**：最后一个子 Agent 提交时，宿主计算一次清单并作为主 Agent 会话消息随同检查点保存；主 Agent 修改后或压缩后可再次调用。检查项：缺失译文、原文数字未出现在译文中（中文数字与 `万/千/亿` 缩放、`11:00`→`11点`、`mid20s` 这类字母粘连片段均按等价处理）、与原文完全相同（未翻译）、长度比例偏离中位数 3 倍以上、违反共享规范中显式术语决定（`源术语 = 译名`，也支持 `->`、`→`，备选译名用 `/` 分隔；拉丁字母术语按整词匹配，`MA` 不会命中 `market`，`long` 不会命中 `long-term`；`X = X` 这类保留原文的说明不参与检查，避免中英混排产生必然误报）；并附每个分派交界前后各 3 条的双语对照。清单最多 80 条、受输入预算 15% 约束，截断时 `issue_counts` 仍统计全部条目。**清单是启发式提示，不代表语义审查完成**，可能存在误报和漏报。
- 提示词要求主 Agent 先处理清单，再重点检查跨片段一致性和发现问题的片段；子 Agent 已自查的片段可以略读。
- **逐页验收检查点 `record_review({offset,count,revision,summary})`**：主 Agent 解读双语页后，显式记录已审范围、累计结论和未解决问题，再读下一页。`count` 必须使用实际返回的 `returned_count`，而不是请求页大小；宿主检查范围确实已通过双语工具返回且版本有效。读取本身不会自动算作语义审查。检查点持久化已审范围、累计摘要及 `next_review_offset`；压缩/重启后从该位置续审，不从第一页重新开始。修改译文会使受影响条目的读取/已审证据失效，其他条目的进度保留；原全文验收仍整体失效。该工具不代替 `accept_translation`，宿主仍无法证明语义审查充分。
- 自动清单的版本、问题数量和问题/边界位置也持久化；压缩后无须仅因历史被清除就重新生成整份清单，修改译文后再重算。
- **一回合收尾**：确认后在同一回合依次调用 `accept_translation`、`close_subagents`、`validate_translation`、`finish_translation`（工具按顺序执行，前一步失败则后续工具报错，不会越过验收）。原先四个大上下文回合合并为一个。

验收与关闭：

1. `accept_translation({review})`：记录主 Agent 对当前译文修订的语义验收摘要；要求子任务全部完成、译文覆盖完整。
2. `close_subagents()`：必须先验收，随后关闭子会话并释放对话和笔记，保留提交结果。
3. `validate_translation()`：结构校验当前修订。
4. `finish_translation()`：只有当前修订已验收、子 Agent 全部关闭且结构校验通过才能提交。

**修改译文会使原验收和结构校验失效**，需要重新验收和校验。程序不能判断验收摘要是否代表真正充分的语义检查；语义审查仍依赖主 Agent，结构校验不代表译文必然正确。

## 子 Agent：隔离并行翻译

每个子 Agent 收到相同的共享规范、自己片段的说明，以及独立虚拟文件：

| 文件 | 内容 | 权限 |
| --- | --- | --- |
| `source.json` | 自己片段的 `{cue_id,start,end,text}` | 只读 |
| `translations.json` | 自己片段的 `{"cue_id":"译文"}` | 可编辑 |
| `notes.md` | 计划、术语和进度笔记 | 可编辑，有大小限制 |

- **首批原文预载**：宿主将自己片段的首批原文直接放入子 Agent 角色消息的 `initial_source_page`，无须先调用 `read_file` 才能开始翻译。预载最多 200 条，受输入预算的 20%、译文输出预算以及角色/工具提示开销共同约束；`next_offset` 是片段内位置，后续可从该位置显式分页读取。单条原文无法满足预载预算时返回空页、`next_offset=0`，仍可用原有工具读取。
- 预载页跨回合、重启和上下文压缩保持相同，不随草稿进度滚动，以保留稳定提示前缀；恢复时结合 `workspace_status` 和已保存译文续翻，不能把预载当成尚未完成的工作。原文始终是非可信任务数据，不授予额外指令或写权限。
- 子 Agent 提示词鼓励直接翻译预载内容，首回合即可 `write_file(merge=true)`；按上下文和输出预算尽量整页批量写入，减少小批写入、重复读原文与例行进度笔记。必要的上下文检索、术语记录和压缩恢复笔记仍可使用。**仍须检查实际保存的译文、修正语义问题，再执行结构校验和显式提交**，主 Agent 验收不变。此优化允许省去首轮原文读取，不保证真实模型一定遵循或达到固定加速比。
- 文件工具包括 `read_file`、`search_file`、`write_file`、`edit_file`。`read_file` 没有默认读取量，Agent 必须显式选择 `count`：原文/译文每次 1～200 条字幕，笔记每次 1～4000 字符；超出范围会报错，内容过长时仍按上下文预算缩小实际返回量，按 `next_offset` 续读。
- `write_file` 的 `merge=true` 支持分批追加；精确编辑要求唯一匹配且不重叠。
- `read_context` 可以按全局字幕位置分页读取或搜索全文，查找前后定义；分页读取同样必须由子 Agent 显式选择 `count`（1～200 条，无默认值），关键词搜索无需 `count`；全文始终只读。
- 子 Agent **不能写入其他片段编号**，也没有分派更多子 Agent 的工具。
- 子 Agent 校验并显式提交自己片段后，宿主复核再合并。未提交草稿不合并，更不会发布给浏览器。
- **已提交片段预览**：任一子 Agent（开头 Agent 优先）完成自查、结构校验和显式提交后，宿主将该片段与检查点同事务保存到 `preview_cues`，发送 `provisional: true` 的 `cue`；无须等待主 Agent 验收。主 Agent 验收期间的修正也会刷新对应预览。预览尚未通过主 Agent 全文审校，不计为全文成功；未提交的子 Agent 草稿始终不展示。
- 原文、编号和时间轴由宿主掌握，不交给模型重写。

## 并发、持久化与恢复

- 主 Agent 每次执行一个模型回合；子 Agent 阶段由各子任务独立循环，完成自己的模型/工具回合并保存后立即进入下一回合，不等慢速兄弟任务。只在所有子任务完成后汇合，交回主 Agent 验收。
- 每个子回合（包括错误状态）完成后，将当前主/子会话、草稿和笔记保存为 SQLite 检查点；保存串行化且按入队时快照写入，防止旧快照覆盖新进度。重启只可能重做尚未保存的在途回合，不重译已提交的开头或其他子任务。
- 单个子任务临时失败最多重试两次，退避只阻塞自己，不阻塞其他子任务；遵守有界 `Retry-After`。重试耗尽或永久错误会使整个任务失败，不发布未验收的全文；已经自查提交的片段预览保留，可观看并续翻，但仍不是最终版本。
- 手动续翻恢复主、子会话和草稿；已完成子任务不重新翻译。可以重新尝试失败的子任务，但**不重置累计模型请求预算**。
- 主、子 Agent **默认关闭累计请求次数限制**（`0`），仍记录所有回合、普通文本回复与重试的实际调用数。可显式设置 1～1000 次上限，所有 Agent 共用一个池子，不是各自一份。关闭此限制不影响单次请求超时、临时失败重试上限或 Token 配置，但可能增加 API 费用。
- 旧任务的有限预算耗尽不是 API 余额或 Token 耗尽。扩展设置中的「Agent 任务请求预算」可填 `0` 关闭限制，或填 `512` 等更高上限，保存后重新开启翻译；留空继承服务端设置。服务端也可在 `.env` 设置 `TRANSLATION_REQUEST_BUDGET=0`，重启服务（Docker Compose 需 `docker compose up -d --build server` 重新创建容器），再以相同视频和翻译设置点击开始，从已保存工作区续翻。累计调用数不会清零。
- 失败时 `published_cues=0`、`failed_cues=全部条数` 表示未完成验收和原子发布，不代表检查点里的草稿已丢失。即使草稿覆盖完整，也必须续翻完成子 Agent 提交、主 Agent 验收和关闭，不能直接将草稿当作成功结果发布。此时扩展会说明「已提交的 N/M 条预览字幕仍可观看，重新开启翻译会从检查点续翻」，预览不会被清空。
- SSE / WebSocket 请求可用整数 `translate_request_budget` 显式覆盖上限；`0` 关闭限制，1～1000 启用上限；优先级为请求值 → `TRANSLATION_REQUEST_BUDGET` → 原任务上限（新任务默认关闭）。未提供覆盖配置的旧任务保留原有上限，需显式传 `0` 或设置环境变量来关闭。预算不参与缓存键；调整不会创建新翻译任务，也不会改变正在运行任务的上限。
- **每轮共享 Token 预算默认 2000 万**：所有主/子 Agent 的输入、缓存输入、输出（含推理）累计计数。优先级为 `translate_token_budget` → `TRANSLATION_TOKEN_BUDGET` → 原任务配置/新任务默认值；非负安全整数，`0` 关闭。旧运行中检查点未配置时仍不限额；手动续翻时补上默认值。此预算不参与缓存键，运行中附着不更改上限。
- Token 额度耗尽时停止发起新请求，已在途的并发请求仍完成并保存，所以可能小幅超额，并非精确账单硬上限。优先按模型报告的 usage 计数；未报告有效 usage（含失败调用）则保守计入估算输入加整次输出上限。计数独立持久化，不依赖上下文历史，不随压缩清零。
- **Token 耗尽保留草稿，用户重新开启翻译后重置本轮 Token 预算并续翻**。自动重试、断线重连和服务重启均不重置；终身 Token 用量和请求次数仍累计保留。请求次数上限独立生效，不因 Token 重置而重置；主动取消仍清除检查点并重新开始。
- 上下文过长时丢弃旧对话，保留文件、笔记、共享规范、分工及主 Agent 的规划/验收检查点。主 Agent 另尽量保留最近一组完整模型/工具回合（受预算约束，不保留孤立工具结果），以便解读最近返回的一页。无法保留时依靠累计摘要和已审范围续做，而不是重读全文。
- **主 Agent 空转止损**：规划/验收连续 4 轮无实质进展时提醒，连续 12 轮则在下一次请求前停止；但若验收已覆盖全部字幕且译文完整（`workspace_status.ready_to_submit: true`），收尾阶段放宽到 24 轮，因为此时只剩一回合的 `accept_translation → close_subagents → validate_translation → finish_translation`，提前失败会丢弃已完成的全文。规划阶段最多 24 轮，验收阶段最多 `max(48, ceil(字幕条数 / 20) * 4)` 轮。重复读同一范围、纯文本、工具报错、改写笔记/摘要和重复结构校验不重置无进展计数；新增读取/已审范围、实际修改译文、派发、验收或提交才算进展，阶段总上限仍防止反复修改循环。止损以失败状态报告并保存草稿、预览和恢复检查点，不自动验收或发布；失败信息会区分「验收未完成」与「已全部审完但未收尾」。用户检查模型能力后可重新开启续翻，显式续翻重置止损计数，不重置累计请求预算。已有运行中检查点在升级后按新机制开始计数，不把历史 100 多轮直接当作超限。
- 新任务使用 `subtitle_translation_team`、`streamOpening: true` 和 `subtitle-translation-team-v2-streaming` 独立缓存版本。历史团队任务仍可恢复，不强行补派开头 Agent；其原有片段改用独立推进。旧单 Agent、固定阶段流程与规则原型已删除，不再注册或恢复；这些历史任务需使用当前团队模式重新开始。

## 模型、安全与发布

- 使用 `pi-ai` 的 OpenAI-compatible Chat Completions SSE + Function Calling，不强制 `response_format`。主、子 Agent 使用同一模型和 token 配置；推理强度可分别用 `TRANSLATION_MAIN_REASONING_EFFORT=high` 和 `TRANSLATION_SUBAGENT_REASONING_EFFORT=medium` 设置。
- 角色推理设置未指定或留空时继承 `TRANSLATION_REASONING_EFFORT`（默认 `off`），显式 `off` 表示该角色不发送推理强度参数。有效设置在任务创建时持久化，修改任一角色档位会隔离新任务缓存；重启、续翻仍使用任务原设置，旧任务不受新增环境变量影响。支持 `off` / `minimal` / `low` / `medium` / `high` / `xhigh`，实际档位需模型支持。
- 模型优先采用请求设置，再采用 `TRANSLATION_AGENT_MODEL`，最后回退为 `sol`。端点需允许最多 10 个并发请求（开头 1 + 后续 9）；限流可能降低收益，真实加速比取决于模型服务与任务分段。
- 默认上下文 128,000 tokens、最大输出 16,384 tokens；由 `TRANSLATION_CONTEXT_TOKENS` / `TRANSLATION_OUTPUT_TOKENS` 配置。预算采用保守估算，不是精确 tokenizer。
- 单次模型请求总时限 10 分钟。截断或缺少完整结束标记的调用不会执行工具。
- 模型端点受部署环境 `OPENAI_BASE_URL` 限制，禁止重定向。字幕、标题、笔记、共享规范与工具结果是任务数据，不是系统指令。
- 浏览器密钥保存在 `chrome.storage.local`；Worker 仅在内存中保存密钥，不写入会话、检查点或日志。重启后必要时由浏览器重新附着提供密钥。
- 服务端默认端口 `8787`，进程内内置 Worker。外部字幕时间戳统一为毫秒。
- 翻译期间推送原文、每个已保存回合的进度，以及已提交片段的预览（开头优先），不展示未提交草稿正文；最终提交后统一发布全文 `cue`（`provisional: false`）和 `done`。扩展按原 `index` 覆盖预览，立即刷新当前字幕，不重复追加。重连会重放已保存的预览；只有最终完成才发送 `done`。
- 进度包含当前阶段、已保存草稿条数、已提交子 Agent 数、可先观看的预览条数、累计推进回合及重试/失败数；不是模型 token 级实时状态。草稿计数包含尚未提交的子任务工作区，合并后不重复计数；主 Agent 验收阶段以合并工作区为准。
- SSE / WebSocket 断开只分离观察者，不取消后台任务；显式取消会中断所有运行中的模型调用，清除预览和续翻检查点，不发布全文。

## 实现与验证

- `worker/translation-team.ts`：团队提示词、开头分派/验收/关闭工具、独立推进调度和任务定义。
- `worker/document-stream.ts`：预览增量重放、重连和最终全文覆盖。
- `worker/subtitle-agent.ts`：主/子 Agent 共用的文件工具、会话管理与上下文压缩，不再包含独立任务定义。
- `worker/document-task.ts`：持久化、累计预算、取消、恢复与原子发布。
- `worker/agent-worker.ts`：团队任务入口、缓存身份和团队任务恢复。
- `worker/job-document.ts`：团队与流式观察者共用的持久化任务文档。
- `worker/translation-review.ts`：双语对照读取、共享规范术语解析与启发式验收清单。
- `worker/team-progress.ts`：主 Agent 规划摘要、实际读取范围、显式验收进度及修订失效处理。
- `tests/translation-progress.test.ts`：560/2054 条字幕强制反复压缩恢复、完整分段候选、逐页确认/编辑失效、空转止损及「已全部审完但未收尾」的收尾窗口。
- `tests/translation-review.test.ts`：对照分页/预算、术语解析（数字逗号、保留原文说明）、中文数字/缩放/时钟等价、整词匹配、各类清单标记与截断。
- `tests/translation-team.test.ts`：已提交片段预览、清单自动附加、对照审阅、一回合收尾、分段覆盖、首批预载/预算缩页/本地分页偏移、首回合批量写入后自检提交、稳定前缀与压缩恢复、越界写入、验收关闭、失败隔离、预算和历史兼容。
- `tests/translation-streaming.test.ts`：开头 + 9 路并发、快任务不等慢任务、逐回合保存、独立退避、预览先发/重连/重启/最终替换和取消。
- `tests/extension.test.ts`：预览立即渲染、最终覆盖与导出不重复。

自动化测试使用本地受控模型，不消耗真实外部模型 token；真实速度和翻译质量仍需用实际模型与视频评估。
